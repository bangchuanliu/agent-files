# Peer Feedback

Write a truthful, strength-led peer-feedback document about a colleague. Ground every strength in a concrete instance and preserve only confirmed specifics.

Source of truth: read [`reference.md`](reference.md) before writing. It contains the exact template, section craft, DO/DON'T rules, phrase bank, and worked example.

## Workflow

1. **Read the raw material.** Accept pasted notes, a file path, or an existing draft.
2. **Establish metadata.** Infer or ask for colleague name, review period (`YYYY-MM`), reviewer, and working relationship.
3. **Map notes before prose.** Sort material into context, 2-4 strength themes, outcomes, metrics, and one forward-looking growth stretch.
4. **Interview once before drafting.** Ask a lean, batched set of questions for missing examples, outcomes, metrics, review period, relationship, and the next-level stretch. Wait for the answer.
5. **Write after the interview.** Use the template in `reference.md`; keep the whole document under 600 words.
6. **Save and report.** Save as `{name}_{YYYY}_{MM}.md`. Use the user's named folder when provided; otherwise use `/Users/banliu/Documents/linkedin/peer-feedback/` if available, with `peer-feedback/` in the current workspace as the portable fallback. Report any qualitative spots that would land better with a number or concrete example.

## Drafting rules

- Lead with impact and strengths.
- Use concrete instance -> impact, not trait -> praise.
- Preserve the user's numbers exactly; invent none.
- Keep Growth and Development to one thin, positive, forward-looking opportunity.
- Tie at least one strength and the growth note to a genuine LinkedIn value from `reference.md`.
- Drop strengths that remain only general traits after the interview.

## Existing drafts

If the user provides a draft that is already close, polish it against the same rules: convert vague praise to examples, compress growth into one forward-looking note, tie strengths to a LinkedIn value, remove personality judgments or peer comparisons, keep it under 600 words, and flag missing examples instead of filling them in.
